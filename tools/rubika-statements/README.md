# بات روبیکای صورت‌حساب همکاران

این سرویس مستقل از افزونهٔ اعلان پروژه اجرا می‌شود و از [قرارداد صورت‌حساب](../../docs/collaborator-statements.md) استفاده می‌کند. در روبیکا یک دریافت‌کنندهٔ `getUpdates` برای هر توکن اجرا کنید. برای آزمایش یک بات جداگانه داشته باشید تا صف پیام‌های بات عملیاتی خوانده نشود.

## راه‌اندازی

- Node.js 24 و Playwright لازم است. Playwright را در محیط اجرا نصب و با `npx playwright install chromium` مرورگر را آماده کنید. روی ویندوز می‌توان برای رندر آفلاین از Edge نصب‌شده با `ZIGGURAT_CHROMIUM_CHANNEL=msedge` استفاده کرد.
- تنظیمات را در محیط خصوصی سرویس یا مدیر اسرار نگه دارید. توکن روبیکا در `ZIGGURAT_RUBIKA_TOKEN` و نشانی HTTPS وردپرس، نام کاربری و Application Password در `ZIGGURAT_STATEMENTS_ORIGIN`، `ZIGGURAT_STATEMENTS_USER` و `ZIGGURAT_STATEMENTS_APP_PASSWORD` قرار می‌گیرند. حساب وردپرس فقط قابلیت `zigurat_read_collaborator_statements` لازم را دارد.
- `ZIGGURAT_STATEMENTS_DB` مسیر مطلق SQLite در پوشهٔ خصوصی سرویس، خارج از Document Root و Git است. دسترسی فایل و پوشه را به سرویس و مدیران مجاز سیستم محدود کنید. پایگاه داده به توکن بات وابسته است. پس از تغییر توکن، اتصال‌های خصوصی را دوباره تأیید کنید.
- از این پوشه یک نمونهٔ `node bot.cjs run` را اجرا کنید. بات هر پنج ثانیه رویدادهای روبیکا را بررسی می‌کند. PDF در حافظه تولید می‌شود. سرویس فایل را فقط به مقصد HTTPS روبیکا بارگذاری می‌کند و لینک عمومی تولید نمی‌کند.

## تأیید حساب خصوصی

1. مدیر شناسهٔ عددی همکار را از فهرست رسمی سایت برمی‌دارد و `node bot.cjs invite 123` را اجرا می‌کند. کد یک‌بارمصرف ۳۰ دقیقه اعتبار دارد.
2. مدیر کد را از کانال احراز هویت‌شده به همان همکار می‌دهد. همکار در گفتگوی خصوصی بات عبارت `اتصال <کد>` را می‌فرستد.
3. مدیر با `node bot.cjs approve` کد را وارد می‌کند، حساب روبیکای نمایش‌داده‌شده را مستقل با هویت همکار تطبیق می‌دهد و شناسهٔ همکار را برای تأیید وارد می‌کند. نام نمایشی روبیکا به‌تنهایی برای احراز هویت کافی نیست. هر حساب و هر همکار فقط یک اتصال تأییدشده دارند.
4. همکار در همان گفتگوی خصوصی «صورت حساب» می‌فرستد. برای لغو اتصال و کدهای معلق از `node bot.cjs revoke 123` استفاده کنید. برای تغییر حساب ابتدا اتصال قبلی را لغو کنید.

مدیر تأییدکننده باید به محیط اجرای سرویس دسترسی مجاز داشته باشد. تأیید از خط فرمان انجام می‌شود.

## دریافت در گروه پروژه

پس از نصب نسخهٔ دارای مسیر `rubika-project-group` روی وردپرس، مدیر می‌تواند همان گروه اعلان پروژه را برای دریافت صورت‌حساب فعال کند. در تنظیمات خصوصی سرویس، `ZIGGURAT_STATEMENT_GROUPS` را به شکل یک شیء JSON از شناسهٔ گروه به شناسهٔ عددی همکار ثبت کنید. نمونهٔ ساختگی آن `{"g0Example":123}` است. نبود این متغیر ارسال گروهی را غیرفعال می‌کند. تغییر گروه اعلان پروژه نیازمند تأیید دوباره در تنظیمات سرویس است.

در گروه فعال، فرمان `@BotUsername صورت حساب` را با نام کاربری واقعی بات بفرستید. بات نوع گفتگو را از روبیکا و انتساب همکار را از سایت بررسی می‌کند. همهٔ اعضای گروه می‌توانند فرمان را بفرستند و PDF را ببینند.

## آزمون

`node --test bot.test.cjs` آزمون‌های اتصال، کنترل مقصد، جلوگیری از پردازش تکراری و قرارداد REST را با پاسخ‌های شبیه‌سازی‌شده اجرا می‌کند. برای رندر واقعی PDF ساختگی، مسیر خروجی را در `ZIGGURAT_TEST_PDF` تنظیم کنید. فایل آزمایشی هیچ‌جا ارسال نمی‌شود.

در آزمایش یکپارچهٔ بعدی، دریافت نوع گفتگوی خصوصی و دامنهٔ مقصد بارگذاری را با توکن بات آزمایشی بررسی کنید. پاسخ مبهم ارسال به‌صورت خودکار تکرار نمی‌شود. همکار می‌تواند درخواست تازه‌ای بفرستد.
